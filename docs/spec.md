# Astro-Notepad 仕様メモ

Astro製ブログ向けのシンプルなエディタ。MITライセンスで公開する。

## 決まったこと

### 対象と配布

- 対応OSはAndroidとLinux(Kubuntu)。Linuxはバイナリを実行して使う
- ブランチ管理はGit-Flow

### 技術

- SCITLと同じTauri 2 + React + Vite + TypeScriptで作る。編集欄はCodeMirror 6
- SCITLの書き出し処理(Androidのzip)、トークン、アイコン、フォント、ビルド用スクリプトを流用する
- 外部との通信はすべて止める。必要になったら、その時に開ける
  - CSPで通信先をアプリ内(Tauriのアプリ本体・IPC・ローカル画像の読み込み)に限る
  - フォントとアイコンはアプリに同梱し、CDNから読まない
  - 本文中の外部画像は読み込まず、生のHTMLは描画しない
  - Tauriの外部通信用プラグイン(httpなど)は入れない

### 範囲

- Git関連の機能はMVPに含めない。その先も積む予定は無いが、あとから足せる余地を残した設計にする
- 編集できるのはこのアプリで作った記事だけ。外部の.mdは読み込まない
- Astroのプレビューは入れない。カスタムCSSも読み込まない
- ふつうのMarkdownのプレビューも置かない。編集欄で装飾のスタイルをその場で当てるので、書いた画面で仕上がりが分かる
- 画像の管理画面はいったん作らない。本文の画像は次の方法で`src/assets/{slug}/`にコピーし、本文に`![](...)`を入れる
  - ツールバーの挿入ボタンからファイルを選ぶ(Android・Linux共通)
  - Linuxではクリップボードからの貼り付けとドラッグ&ドロップも受け付ける
- 画像のファイル名は記事ごとの連番(`01.png`など)にする
  - 挿入・貼り付け・ドロップのどれでも連番にそろえる
  - 番号は記事内の最大の番号+1。消して空いた番号は詰めない
  - 名前の書き換えは、画像の管理画面を作るときに合わせて入れる。書き換えたら本文中の参照も合わせて書き換える

### 記事の保存と書き出し

- 記事のディレクトリ名をslugとして使う
- slugに使える文字は英小文字・数字・ハイフン。記事を作るときに入力し、あとから変更もできる
- 出力の形は以下。リポジトリの直下に重ねれば取り込める

  ```
  ./{slug}/src/content/posts/{slug}.md
  ./{slug}/src/assets/{slug}/
  ```

- Linuxは実行ファイルの場所に上の形で書き出す。リポジトリへ直接書き込む機能は付けない
- Androidは書き出し機能(zip)を付ける
- 自動保存する。間隔は仮に、2分ごとと、入力が止まってから15秒後とする
- 記事を切り替えるときとアプリを閉じるときは、保存していない変更があれば確認のダイアログを出す(保存する/保存しない/キャンセル)
  - 「保存しない」で捨てるのは、最後の自動保存より後の変更だけ
- 上書きの前に直前の1世代をバックアップとして残す。バックアップは書き出しの形の外に置き、リポジトリに重ねたときに入り込まないようにする

### フロントマター

ユーザーにフロントマターを書かせない。

- title: 左上のH1。書き換えるとそのまま反映する
- description: タイトルの下に置く
- 任意の項目は、MVPではheroImageだけ入れる。項目は[astro-blog-frontmatter.md](astro-blog-frontmatter.md)を参照
- MVPの後で、残りの任意の項目(updatedDate)を入れる。そのとき、heroImageも含めて任意の項目ごとに設定画面で有効・無効を切り替えられるようにする
- pubDateとheroImageは、説明の下に仕切り線で挟んだ一行で並べる。pubDateは日付の入力欄、heroImageは画像を選ぶボタン

### 画面

大まかな見た目は、Artifactsの試作(https://claude.ai/artifact/8bn9qixundRorooQHvkTdF)で固めた。

- 画面とダイアログは次のとおり
  - 編集画面(デスクトップ・Android)
  - 記事一覧(デスクトップはサイドバー、Androidは左から引き出す)
  - 設定画面
  - 新しい記事のダイアログ(slugの入力)
  - 保存の確認のダイアログ
- 記事一覧はサイドバーに置く。デスクトップでも折りたためるようにする(おおむねSCITLと同じ)
  - 各記事はタイトル、slug、日付を出す。一覧の上に新しい記事のボタン、下に設定への入口を置く
- 編集画面はタイトル(H1)、説明、pubDateとheroImageの行、本文の順に並べる。本文の幅は最大720px
- ツールバー
  - 置くのは見出し、太字、斜体、箇条書き、引用、リンク、画像の挿入。Androidは斜体を除く
  - デスクトップは編集画面の上、Androidは下(キーボードのすぐ上)に置く
  - デスクトップはツールバーの左端にサイドバーの開閉ボタン、右端に保存の状態(「保存済み 14:32」など)を出す
- Androidは上のバーに記事一覧を開くボタン、保存の状態、その他のメニュー(zipで書き出す、設定)を置く
- 設定画面は置く。今のところ中身はライセンスの表示だけ(このアプリと、使っているライブラリ・フォント)
- 新しい記事のダイアログでは、slugに使えない文字が入るとその場で知らせ、書き出し先のパスも見せる
- 保存の確認のダイアログは「キャンセル」「保存しない」「保存する」の3つ

### 見た目

基本はSCITL(`~/Documents/SCITL-2.0`)にならう。

- Markdownのレンダリングは最小限にする。記号は消さず、スタイルと画像の表示だけを付ける
- フラットデザインにする。SCITLの塗りの段差や影は使わず、文字と最低限の仕切り線で表す
- 色は白(HSV(0,0,98))と黒(HSV(0,0,0))を基本に、灰色と淡いアクセント色を使う
  - 文字の灰色は、ライト`#707070`(明度44%、白地と4.7:1)、ダーク`#8C8C8C`。明度50%だと白地と3.8:1で、小さい文字に要る4.5:1に届かないため
  - 仕切り線は、ライト`#E0E0E0`、ダーク`#262626`
- 書体

  | 箇所 | 書体 | ウェイト |
  |---|---|---|
  | 見出し・太字 | Noto Sans JP | 500 |
  | 画面の文字(ボタン・メニューなど) | Noto Sans JP | 400 |
  | 上記以外(本文など) | Noto Serif JP | 400 |

- アクセント色のシードはHSL(35,95,55)(`#F99E1F`)。画面に出すのは2〜3か所に留める
  - 明暗それぞれの色は、色相を保ったまま、地の色とのコントラストが目標の値になる明度でとる
  - ライト: `#D57C00`(HSL(35,100,42))、白地と3.0:1。鮮やかさを優先したため、小さい文字には使わない(4.5:1に届かない)
  - ダーク: `#F99D1D`、黒地と9.9:1(シードとほぼ同じ)
  - 選択範囲の淡い塗りは、ライト`#F0DFC8`、ダーク`#3E2D16`
  - 使う場所は仮に、選択中の記事の左の印(塗りは使わない)、カーソル、フォーカスの枠、選択範囲の塗り。リンクは文字色を変えず下線だけ付ける
- アイコンはGoogleのMaterial Symbols
- ダークテーマ(黒地に白)を用意し、OSの設定に合わせて切り替える
